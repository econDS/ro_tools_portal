# Project instructions for Codex

Build ro-tools-portal as a static portal, not a replacement for every app.
Read PLAN.md and docs/ before implementation when present; they are kept locally and are not in the public repository, so if absent follow this file, README.md and integrations/nav/README.md. Respect evidence limits in data/sources.json.
Do not change existing repositories during portal-only work. For a child-repo task, work only in its selected checkout and preserve unrelated edits.
Do not create/push remote repositories, change GitHub Pages settings or deploy unless separately authorized.
Do not use git reset --hard, git clean, force push or overwrite user data to make integration easier.

No iframe hosting, forced framework migration, monorepo copy, shared unversioned warehouse, or unversioned runtime remote executable code.
Use real HTML anchors with graceful fallback. A portal/catalog error must not disable any calculator.
Do not invent active-event status, live HTTP check results, game-rule verification dates, tool capability support or deployed URLs.
Keep grade-refine planned/non-launchable until a real target is verified. Preserve Ocean's docs publishing source and observed master branch unless explicitly changing them in a separate reviewed task.
Do not change existing calculation output as a side effect of UI/navigation work.
Never localStorage.clear(). Keep existing app keys; read/write only owned, documented keys and explicit import contracts.
Namespace/Shadow DOM are not security boundaries. Validate URLs, schemas and untrusted imports; avoid innerHTML for catalog/payload text.
Keep game-rule ownership in the app; do not add a global event flag that conflates Spotlight and Refine events.
Do not count Refine costs twice when linking Dim Glacier to Grade/Refine. Material plans are not automatically equipment states.
Declare capabilities only when implemented and tested. Existing custom export/import support is not suite schema support.
Use Thai UI, retain proper item/product names, and make all controls keyboard accessible.
At each milestone report actual changed files, actual test commands/results and what was not tested. Do not claim design-kit validation is app E2E testing.
