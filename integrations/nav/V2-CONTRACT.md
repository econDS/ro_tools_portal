# Dynamic navigation 2.0.0 contract

The canonical source is data/tools.registry.v1.json. Portal builds publish catalog/v1/tools.json from it. Schema major 1 remains compatible: catalogVersion, tools with stable id, title, canonicalUrl, listingStatus (listed/planned), optional identity (bundled icon name and accessible hex accent). Registry array order controls navigation order; hidden entries are omitted, planned entries have null URLs. No per-tool executable code or URL allowlist exists.

Every newly connected local component immediately renders its immutable bundled fallback and fetches https://econds.github.io/ro_tools_portal/catalog/v1/tools.json, even before opening. No catalog-url configuration is necessary (the central endpoint is fixed). Requests omit credentials/referrer, reject redirects, revalidate HTTP cache (cache:no-cache), and abort after 1500ms including body reads. JSON requires HTTP success, exact response URL, application/json, at most 262144 streamed bytes and 500 tools. Invalid updates leave fallback intact. Reload retries; there is no persistent catalog cache or background timer. CDN freshness depends on Pages revalidation; service workers must not cache/intercept this endpoint. The Portal service worker already excludes it.

Raw canonical URLs must match https://econds.github.io/[A-Za-z0-9][A-Za-z0-9_-]*/ exactly, at most 256 characters. Other origins, nested paths, encoded characters, dot segments, credentials, explicit ports, whitespace, queries and fragments are rejected before URL normalization. Adding another repository on this approved origin needs registry review only. New origins/path shapes require a reviewed component release.

A stable tool-id can be unknown in the fallback: its literal ID is shown until remote metadata resolves it. Renames update identity; removal returns to literal ID and removes the destination; no fabricated link is made. Identity omitted remotely may reuse the fallback icon for the same stable ID. Text is rendered with DOM APIs only.

Existing theme and alignment APIs remain. Menu is closed initially, contains a search input (aria-label ค้นหาเครื่องมือ) and a bounded scrolling list, maximum min(50vh,320px). Open keeps toggle focus; Tab visits search then links. Escape closes and returns toggle focus. Updates restore the focused destination or search when removed. Portal link stays available outside the menu. No storage, formulas, imports/exports or host shortcuts change.

Release files nav.js, catalog.snapshot.json and nav.lock.json are copied byte-identically to each child's existing publishing root under assets/ro-suite/2.0.0/. Source commit precedes artifact commit; preserve source ancestry (normal merge), all historical release bytes and the existing 1.5.1 installation for rollback. Build:nav never regenerates fallback from live registry. Explicit generate-nav-snapshot is only for preparing a new release before its source commit.

Merge/publish Portal first after review, then child integrations. Catalog-only add/remove/rename/reorder changes require only Portal publish:root and no child rebuild. Roll back a child by restoring its local script path to 1.5.1; rollback loses dynamic discovery but preserves host state. Do not deploy or change Pages settings as part of this preparation.
